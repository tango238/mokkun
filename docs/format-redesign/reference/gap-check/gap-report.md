# 04-yaml-authoring-rules.md ギャップ分析レポート（DADS 突き合わせ）

- 対象ルール: `docs/format-redesign/04-yaml-authoring-rules.md`（以下 04）
- 形式: `docs/format-redesign/02-schema-v2.md`（以下 02）, `schema-v2.json`
- 正解の基準: `reference/dads-components-ux.md`（C:）, `reference/dads-foundations-ux.md`（F:）。必要箇所のみ DADS 原文ダンプで確認（input-text の「氏と名を空白で区切ってください」「確認メール送信で疎通を確認」など）
- 検証対象: `scratchpad/gap/scenario-a.yaml`（住民向け 保育所入所申込）, `scenario-b.yaml`（小売 在庫管理 管理画面）と各決定ログ
- 補助確認: v2 レンダラー（`src/renderer-v2/`）の実挙動（example はサポートテキスト「例: 」で描画、required 未指定は「※任意」、readonly は「編集不可」、states.success と error は同時にバナー描画、一覧セルはダミー生成）

判定の凡例（§1）
- **(a)無視**: 既存ルールで判断できるのに作者が守らなかった（ルールの書き方・チェックリストの弱さを示す）
- **(a)不明瞭**: 既存ルールはあるが、曖昧・矛盾・閾値なしで正しく判断できない
- **(b)ギャップ**: 該当するルールがない
- 右端の「G」は §2 の統合ギャップ ID

### 1.3 傾向

- (a)無視が多いのは R-W01（動詞で終える）、R-W02（文言統一）、R-I05（文字種限定）、R-I13（分岐の予告）、R-V10（具体的な成功文）、§5.1（5 個以下は radio）。どれも §7 チェックリストに項目がないか、あっても粒度が粗い。
- (a)不明瞭は「閾値なし」（R-F07、R-S02、§5.1 の combobox、R-V12）と「ルール同士の衝突」（R-V01×閲覧画面、R-V03×修正のための戻り、R-V13×一括操作、R-I04×02 の example 記述）に集中している。
- (b)ギャップの中心は **定番項目（氏名・住所・メール・同意）** と **画面の型（確認・完了・詳細・ダッシュボード）**。どちらも Field／View 単体のルールでは書けず、項目の組み合わせ方や画面の中身を決める上位ルールがない。
